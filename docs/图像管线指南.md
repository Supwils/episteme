# 图像管线指南（T-IMAGE-01）

> 本文是内容图像的唯一规范。任何要在文章里插图的人（人或代理）都必须按本流程走——这是 `T-SUBJECT-NEXT`（艺术、建筑与美学）的前置闸门，也适用于所有现有领域。

## 原则

1. **每张图都有可核验的权利记录**：作者、来源页、许可证、出处备注，缺一不可。
2. **不允许外链热图**：文章里禁止 `![...](http...)` 直链，必须先登记本地化。
3. **构建期响应式**：变体在构建时生成（640/1280/1920w WebP），不走 next/image 运行时优化。
4. **性能预算硬约束**：单图最大变体 ≤ 500KB，单篇文章图像合计（1280w 档）≤ 800KB，CI 审计强制执行。

## 新增一张图（四步）

**1. 放原图与元数据**（`content-assets/images/`）：

```
content-assets/images/<id>.src.<png|jpg|webp>   ← 原图
content-assets/images/<id>.json                 ← 权利元数据
```

`<id>.json` 形状（Zod schema 见 `lib/image-rights.ts`）：

```json
{
  "title": "图注（中文，渲染为 figcaption）",
  "author": "作者/版权持有人",
  "sourceUrl": "https://可核验的来源页面",
  "license": "public-domain | cc0 | cc-by | cc-by-sa | cc-by-nd | own",
  "attribution": "需要署名时的完整署名行（public-domain/own 可省略）",
  "provenance": "出处备注：获取日期、裁剪/修改说明"
}
```

许可证要点：`cc-by*` 必须填 `attribution`；拿不准许可证就别用这张图。

**2. 生成变体**：

```bash
pnpm gen-content-images   # 幂等，生成 public/images/<id>-<w>.webp + manifest.json
```

**3. 在文章里引用**（无扩展名形式）：

```markdown
![屏幕阅读器与无障碍树可访问的替代文本](/images/<id>)
```

MarkdownRenderer 自动渲染为 `<figure>`：webp srcset、显式宽高（防 CLS）、lazy 加载、图注与署名。alt 文本必填且要有意义（读屏器依赖它）。

**4. 审计**：

```bash
pnpm audit-image-rights   # prepush 与 CI 门禁的一部分
```

校验：登记完整性（schema）、引用一致性（文章引用的 id 必须已登记）、变体新鲜度（原图更新后必须重新生成）、性能预算、外链热图禁令。

## 文件清单

| 位置                             | 作用                                          |
| -------------------------------- | --------------------------------------------- |
| `lib/image-rights.ts`            | Zod schema、路径常量、预算常量、manifest 读取 |
| `scripts/gen-content-images.ts`  | 响应式变体生成（sharp，幂等）                 |
| `scripts/audit-image-rights.ts`  | 审计（在 `pnpm prepush` 链内）                |
| `components/RegisteredImage.tsx` | 文章内登记图像的 `<figure>` 渲染              |
| `content-assets/images/`         | 原图 + 权利元数据（唯一登记处）               |
| `public/images/`                 | 生成产物（变体 + manifest.json），不要手改    |

## 预算修改

预算常量在 `lib/image-rights.ts`（`ARTICLE_IMAGE_BUDGET_BYTES`、`SINGLE_IMAGE_BUDGET_BYTES`）。提额需要在 `docs/任务清单.md` 的决策记录里写明依据，与 JS/CSS 预算同规格。
