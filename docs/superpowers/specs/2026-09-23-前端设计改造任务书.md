# Episteme · 格致 — Front-End Design & Interaction Overhaul

You are the lead front-end engineer and design director for **Episteme · 格致** (repo: `Supwils/episteme`, production: https://episteme-self.vercel.app). The content is excellent and deep: 22 domains in six clusters, ~3,000 articles, a force-directed knowledge graph, reading routes, learning spines L1→L5, research frontiers, and several bespoke 3D/Canvas domains. The front end has grown domain by domain, so it now feels like a collection of good pages rather than one instrument. Your job is to give it one coherent, memorable visual identity and a reading experience worthy of the writing, then build a 3D overview of how human knowledge is structured.

This brief is long on purpose. Read all of it before you start, then work through it in the order given in "Sequencing".

## 1. What I found when auditing the live site

I read the server-rendered HTML of the homepage, `/philosophy`, `/philosophy/thinkers/plato`, `/law`, `/law/foundations/why-law-exists`, `/read`, `/knowledge-graph`, plus `README.md` and `CLAUDE.md`. I could **not** see rendered pixels, so **verify every item below against the running app and the code before acting on it** — some may already be fixed or may be artifacts of how I fetched the page.

### 1.1 Correctness bugs (fix these first — they erode trust in a knowledge site)

- **Stat counters render as `0` in server HTML.** `/philosophy` ships `0位哲学家 · 0个流派 · 0个思想实验 · 0篇文章` (twice). This is almost certainly a count-up animation initialized at 0. Crawlers, no-JS readers, slow devices, and reduced-motion users see zeros. Render the final number on the server; animate only as progressive enhancement, and not at all under reduced motion.
- **The same statistic disagrees with itself across pages.** Homepage philosophy card: "117 哲学家 · 42 流派 · 340+ 篇文章". Philosophy landing explore cards: "67 位东西方哲学家", "33 个流派". Homepage: "3116 深度文章 / 3289 可检索知识单元". README/CLAUDE.md: "2828 篇内容 / 3213 节点". `/knowledge-graph` meta description: "1600+ 知识单元". Create one generated stats source (extend `generated/search-stats.json` or add a sibling produced by `gen-all`) and make **every** count on the site, including meta descriptions, read from it. Add a test that fails if a hard-coded count appears in a page component.
- **Legacy brand string in UI.** Domain landings show the eyebrow `universe · knowledge / law` and `universe · knowledge / philosophy`. "Universe Knowledge" is the old project name. Replace with the current brand system (see §3).
- **Navigation groups don't match the six clusters.** The top nav shows 自然与数理 / 生命与心灵 / 社会与文明 / 人文与艺术 / 探索 — four groups plus Explore — while the homepage, footer, and `lib/data.tsx` use six clusters: 宇宙与自然 / 生命与心灵 / 社会与制度 / 历史与文明 / 人文与艺术 / 数理与技术. Derive nav labels and grouping from `DOMAINS[].cluster` only.
- **Inconsistent breadcrumb root.** Some pages say `知识平台`, others `首页`. Pick `首页` everywhere.
- **Metadata is generic on most article pages.** On `/law/foundations/why-law-exists`, `og:description` is the domain description and `twitter:title/description` are the site default ("探索人类知识的边界：宇宙物理、人类历史、哲学思想、生命科学"). Philosophy articles get a per-article `/api/og` image; engine-driven domains don't. Every article should emit its own title, description, and OG image, via one shared `buildArticleMetadata()`.
- **The article dek is a truncated first paragraph.** The law article's subtitle is the first 150-ish characters of the "破除误解" section, ending mid-thought with "第二个误解，…". Use a real `summary`/`dek` frontmatter field when present; otherwise fall back to the first _complete sentence_, never a mid-sentence cut. Log articles missing a summary for authors.
- **Duplicated disclaimer.** The law article shows the legal disclaimer inline in the body and again at the bottom. Render it once, in a designed notice component.
- **Daily knowledge mislabels and duplicates.** Today's "每日知识" shows two cards for the same event (Neptune's discovery, 1846). One is labeled 📜人类历史 but links to `/universe-physics/knowledge-base/…`. Label from the link target's domain, and dedupe by event.
- **Timeline ordering.** On the philosophy quote timeline, entries are out of chronological order (Marx 1845 before Kierkegaard 1844; Foucault 1976 before Derrida 1967; Wang Yangming 1527 appended at the end). Sort by year in the rendering layer.
- **Era/tradition tags.** In "相关哲学家", al-Farabi, al-Ghazali, and Aquinas are tagged 古代 (they're medieval). In the quote timeline, Averroes is tagged 东方. Fix the taxonomy data if it's a data field; log it for review if it's editorial.
- **Meaningless numbering.** Homepage domain cards read "DOMAIN 01, 02, 15, 17…" — creation order, not a sequence users care about. Drop the numbers (numbering should only mark real sequences, like L1→L5 or reading-route chapters). Also: only mathematics gets a leading glyph (`∑`) on its card — make glyphs systematic (§3.4) or remove them.
- **`/knowledge-graph` is blank without JS** ("正在加载知识图谱…"). Server-render a meaningful fallback: clusters → domains → top hub nodes as links, plus counts from the stats source.

### 1.2 Design & experience problems

- **Two visual languages.** The 12 bespoke domains (philosophy, physics, cosmology…) have rich, individual landings. The engine-driven domains (law, education, religion, arts…) share a plain template: title, description, learning spine list, recently updated, emoji-headed explore cards. Side by side, it reads as two products.
- **Iconography is a mix of emoji (📖 ⚖️ 🏛 🤝 🔍 🌍 🛰 📅) and geometric glyphs (◈ ⬡ ◎ ◇ ▣ ∑ ∞).** Emoji render differently per OS and flatten the tone. Replace with one custom glyph system.
- **The homepage is a long stack of peer sections** (hero, stats, six clusters, five "knowledge continuum" sub-sections with lazy placeholders, daily, updates, featured, features, graph CTA). Nothing is the clear protagonist, and the continuum sections show placeholder text "交互数据在这一部分进入视口后载入" before loading.
- **Two article templates.** Philosophy articles have a quick-facts sidebar, prev/next thinker, related/referenced-by groups. Engine articles have L-level, reading time, "问问这篇" chips, 条目信息, and "正文中引用本条". Both are good; they should be one system with optional modules.
- **Long-form reading needs more structure.** The Plato article is ~11,500 characters (~28 min). It has rich recurring section types (破除误解, 原典引文, 关键洞察, 事实卡, 跨域连接, 参考文献) that are currently rendered as plain headings + paragraphs. Tables that are really diagrams (the Divided Line, collapsed into a 2-row table even though the text describes four levels) lose their meaning.
- **Bold overuse in 跨域连接 sections** (e.g. Plato) — almost every sentence is bold, so nothing is emphasized. Solve at the rendering layer (§6.4), not by editing content.

## 2. Design North Star: 观测台与手记 — The Observatory and the Notebook

The name 格致 comes from 格物致知: investigate things to extend knowledge. The two themes already name the two halves of that act: the **observatory**, where you look out at the structure of the world, and the **notebook**, where you write down what you understood. Every design decision should serve one of those two halves.

- **Observatory surfaces** (homepage, domain landings, graph, 3D) feel like **brass scientific instruments and star/topographic charts**: precise line work, engraved scales, concentric structures, measured motion.
- **Notebook surfaces** (articles, reading routes) feel like **a scholar's annotated notebook**: calm text, generous margins, marginalia, index cards, seal stamps, restrained color.
- **One geometry underlies everything.** The homepage instrument (§5), the domain landings (§6), and the 3D summit (§8) all use the _same_ spatial model of knowledge: angle = discipline, distance/height = cognitive stage. A reader who learns the map on the homepage recognizes it everywhere else. Put this model in one module, `lib/knowledge-geometry.ts`, with unit tests, and have every visual consume it.

### Principles

1. **Structure is information.** Rings, ticks, numbers, and lines must encode something real (cluster, domain, level, sequence, link). No decorative numbering, no decorative dividers.
2. **Spend boldness in one place per page.** The homepage's bold thing is the instrument. A domain landing's bold thing is its specimen plate. An article's bold thing is the text itself. Everything around the bold thing stays quiet.
3. **Motion answers the reader.** One orchestrated entrance per page, at most. Beyond that, motion only responds to an action (hover, drag, open, navigate) and shows what changed. No fade-up-on-scroll on every section; no hover lift on every card.
4. **Truthful by default.** Server HTML must be complete and correct without JS. Animation is enhancement, never the only carrier of information.
5. **Fast is part of beautiful.** Respect the budgets; prefer SVG and CSS over WebGL everywhere except the 3D view and existing 3D domains.

### Anti-patterns to avoid (these read as templated)

Identical rounded cards with the same soft shadow everywhere; gradient washes as decoration; tracked-out uppercase eyebrow labels above every heading; `A · B · C` meta strings as a universal pattern; a `→` glued to every link; emoji as icons; a single word in a headline highlighted in a different color; near-black `#111` backgrounds with one neon accent. Some of these exist today — replace them as you touch each surface.

### 3.2 Typography (CJK-first)

- **Body**: system serif CJK stack first (`"Songti SC", "Noto Serif CJK SC", "Source Han Serif SC", serif`) — zero download cost on macOS and most Android. Pair with a Latin serif for English subtitles and names (e.g. EB Garamond, or keep the current one if it's already considered). Pick deliberately and document why.
- **Display (headings, the instrument, seals)**: a subsetted web font. Add a build step (a new `gen-*` script wired into `gen-all`, idempotent) that collects every character used in titles/headings/nav and subsets the display font to WOFF2 with `pyftsubset` or `subset-font`. Candidates: Source Han Serif Heavy for the Observatory voice; **LXGW WenKai (霞鹜文楷, OFL)** for Notebook marginalia and handwritten annotations — it's a natural fit for 手记. Budget the result and record it.
- **Measure and rhythm**: body 17–18px, line-height 1.8–1.9 for CJK, measure ~36–40 CJK characters (roughly `max-width: 38em` at body size). Paragraph spacing rather than first-line indent.
- **CJK typesetting as progressive enhancement**: `text-spacing-trim: normal`, `text-autospace: normal` (CJK–Latin spacing), `hanging-punctuation: allow-end` (Safari), `line-break: strict`. Verify behavior in WebKit and Chromium via the existing Playwright configs.
- **Emphasis**: define the look of `<strong>` in prose as weight 600 plus a thin brass underline or marker-style highlight, and offer 着重号 (`text-emphasis: dot`) as an opt-in MDX component for true key terms.

### 3.3 Motion tokens

Define durations (fast 150ms / base 240ms / slow 480ms / orchestrated ≤1200ms total), two easing curves (instrument: `cubic-bezier(.2,.7,.1,1)`; paper: gentle ease-out), and one `useMotionPreference()` hook that every animated component reads. GSAP and Framer Motion are both in the stack: choose one per surface and never add a third animation library.

### 3.4 学科印 — Domain Seals (the new icon system)

Replace every emoji and ad-hoc glyph with **22 domain seals**: small square seal marks in the spirit of Chinese seal carving (篆刻) — one or two characters per domain (物, 宙, 地, 化, 生, 心, 医, 语, 教, 经, 政, 社, 法, 史, 宗, 人, 哲, 艺, 文, 数, 算, 工 — refine the choices), cut in cinnabar or the cluster pigment. Implement as one SVG sprite (or a component rendering a seal from a registry) so it costs a few KB total. Also design a small functional glyph set (reading route, graph, daily, random, search, molecules, timeline, frontier) in the same engraved line style to replace 📖 ◈ ⬡ ◎ ◇ ▣ 📅 etc. Every seal has an accessible name.

### 3.5 标本图版 — Specimen Plates (generative domain art)

Each domain gets a **deterministic generative line drawing**, like an engraved plate in an old scientific atlas, generated from the domain's own subject matter. Pure SVG, seeded by domain id (so SSR and hydration match), themed via tokens, drawn once with a stroke-dash reveal on first view (static under reduced motion).

Starting motifs (refine them; each generator should stay under ~80 lines using shared utilities in `lib/plates/`):

- 物理 field lines and two-source wave interference · 宇宙 nested orbital ellipses with a precessing perihelion · 地球科学 topographic contours and strata · 化学 hexagonal lattice with orbital lobes · 生命 a branching phylogeny · 心理 overlapping receptive-field circles / a Necker-cube line study · 医学 a pulse trace resolving into a Kaplan–Meier step curve · 语言 a spectrogram-like waveform · 教育 the forgetting curve reset by spaced reviews · 经济 crossing supply–demand curves with an equilibrium mark · 政治 a Voronoi partition of territory · 社会 a small-world network · 法 a hierarchy of norms (承认规则 at the root) · 人类历史 stacked timeline strata · 宗教 neutral concentric geometric rosette (no tradition-specific symbol) · 人类学 a kinship diagram · 哲学 a dialectical triad / argument map · 艺术 a perspective grid with a vanishing point · 文学 a Freytag narrative arc drawn as a single stroke · 数学 a Lissajous figure or proof tree · 计算机 a finite-state automaton · 工程 a Warren truss blueprint.

## 5. Epic E4 — Homepage: 格致仪 (the Knowledge Astrolabe)

### 5.1 The hero

The hero is an **interactive astrolabe drawn in SVG** — a brass instrument that _is_ the map of the site.

- **Angle = discipline.** An outer ring of six arcs (clusters, in pigments), a middle ring of 22 ticks with seals (domains). Order the ring so neighbors are genuinely adjacent and it closes on itself: 数理与技术 → 宇宙与自然 → 生命与心灵 → 社会与制度 → 历史与文明 → 人文与艺术 → back to 数理与技术 (logic sits beside philosophy — the loop is real).
- **Radius = cognitive stage.** Five concentric bands for the five stages of the existing knowledge continuum (直觉启蒙 → 核心概念 → 系统解释 → 方法建模 → 综合前沿). **L1 at the rim, the frontier at the center** — the center is where disciplines converge, and that's where the five 知识汇流 topics (AI 治理, 城市气候适应, 人口老龄化, 宏观财政, 公共卫生优先排序) sit as small bright marks.
- **The alidade (pointer)**: drag it, or use arrow keys, to sweep across domains. The selected domain's radius lights up its **learning spine** (the existing L1→L5 steps per domain, e.g. law: 法律为什么存在 → 法治与人治 → 违宪审查 → 比较法的方法 → AI 与算法治理) as five points on that radius, each a real link. A readout panel beside the instrument (`aria-live="polite"`) shows the domain name, its guiding question, and the five steps.
- **Why this geometry**: it's the top-down plan view of the 3D summit in §8. The CTA "登上格致山" transitions from this plan view into the 3D view, so the homepage literally previews the graph.
- **Entrance**: one orchestrated sequence — rings engrave in, ticks settle, the pointer swings to a random domain (≤1.2s). Nothing moves after that unless the reader moves it.
- **Engineering**: SVG rendered on the server from `DOMAINS` + `knowledge-geometry` (complete and legible without JS), hydrated for interaction. No three.js on the homepage. Accessible as a `radiogroup` of 22 domains. Mobile: a half-astrolabe anchored to the bottom of the hero, rotated by horizontal swipe.
- **Headline**: keep "从问题出发" and the existing supporting line; the instrument carries the visual weight, so the type stays calm.

### 5.2 The rest of the homepage — fewer, stronger sections

Restructure into this order and merge the rest:

1. **Hero instrument** (above).
2. **六簇二十二域 — the atlas**: six cluster bands; each domain as a card with its small specimen plate, seal, name, one-line description, and real counts. No "DOMAIN 01" numbering.
3. **今天** — merge 每日知识, 最新更新, and 精选内容 into one "today" band: one hero pick of the day, a short dated list of updates, and a rotating shelf of featured entries. Fix the dedupe/label bugs here.
4. **读完一个主题** — reading routes as book spines on a shelf (spine = domain pigment, title set vertically in CJK, chapter count as ticks). Clicking pulls the book out into a preview.
5. **知识连续体** — collapse the five continuum sub-sections into one tabbed module (主干地图 / 地形与路线 / 可达前沿 / 多学科汇流 / 策展覆盖) with informative skeletons shaped like the final chart instead of placeholder sentences.
6. **登上格致山** — a teaser for §8: the plan-view drawing tilting slightly on scroll (static under reduced motion) with the CTA.
7. Footer.

A "继续阅读" strip appears at the top of section 2 only when localStorage has reading history.

Checkpoint: before building E4, send me (in Chinese) the plan with ASCII wireframes for desktop and mobile, plus the geometry spec, and wait for approval.

## 8. Epic E7 — 格致山 (The Knowledge Summit): the 3D overview

A 3D overview of how the knowledge on this site is structured. Not a hairball: a **mountain** whose shape encodes meaning.

### 8.1 The model

- **Angle (θ)**: cluster sector, subdivided into domain sub-sectors — the same ring order as the homepage astrolabe. Within a domain, nodes spread by section.
- **Height (y)**: cognitive level, L1 at the base to L5 at the top, with a continuous offset by prerequisite depth so chains visibly climb.
- **Radius (r)**: shrinks with level and with the node's share of cross-domain edges. Foundational, single-discipline ideas spread wide at the base; integrative, cross-disciplinary ideas are pulled toward the central axis as they rise. The **summit** is where disciplines meet — the 知识汇流 topics sit there as beacons.
- **Seen from directly above, the mountain is the homepage astrolabe.** That's the design's central reveal.

### 8.2 Rendering

- **Precompute the layout at build time** in a new idempotent `gen-*` step wired into `gen-all`, from the existing graph data and `lib/knowledge-geometry.ts`. Emit compact JSON in `public/` (quantize coordinates to int16; set and record a brotli size budget, target ≤ 250 KB). No runtime force simulation for this view.
- **Nodes**: one `InstancedMesh` (or a points shader) — size by degree, color by cluster pigment, soft glow for hubs.
- **The terrain**: a translucent surface interpolated from node density, shaded with **topographic contour lines** (a `fract(height)` shader) — it ties directly to 地球科学 and to the homepage's existing "知识地形" language. Cheap and beautiful.
- **Edges**: intra-domain edges as faint lines in one merged `BufferGeometry`; cross-domain edges as arcs (bridges) shown on hover/selection or with a "显示桥梁" toggle.
- **Labels**: don't ship multi-megabyte CJK SDF fonts. Use HTML overlay labels (drei `<Html>`) for the 22 domains, the 5 summit topics, and the hovered/selected node only.
- **Camera & intro**: the view opens directly overhead, matching the astrolabe, then tilts to a three-quarter view (once, skippable, skipped under reduced motion). Orbit with damping and a limited polar angle.

### 8.3 Interaction

- Hover → tooltip (title, domain seal, level). Click → side panel: dek, level, prerequisites, neighbors, "开始阅读", "以此为起点规划路线".
- ⌘K integration: selecting a result flies the camera to that node.
- **Lenses**: 按学科 (default) · 按阶段 (color by level) · **我的足迹** (localStorage read history lights up read nodes; unread areas sit under a light fog — the reader literally sees the parts of the mountain they've explored) · **阅读路线** (choose a route; a glowing trail climbs through its chapters in order).
- Optional, only if the data supports it: a **时间透镜** where height becomes the date an idea was first formulated. Check data coverage first and skip it if coverage is low.

### 8.4 Performance, fallbacks, accessibility

- Route: `/knowledge-graph?view=summit` (or `/knowledge-graph/summit`). Keep the existing 2D force graph as "网络视图" — don't delete it.
- three/R3F loaded only on this route via dynamic import; initial route JS ≤ 180 KB gzip.
- DPR clamp `[1, 1.75]`, `frameloop="demand"` when idle, pause when the tab is hidden, drei `PerformanceMonitor` to drop bloom/terrain detail on weak devices. Targets: 60fps on an M1 MacBook Air, 30fps on a mid-range Android phone.
- No WebGL / reduced motion / narrow screen → the 2D plan view (astrolabe SVG with nodes plotted from the same layout).
- An accessible tree (cluster → domain → level → node) with the same select/fly-to/open actions, and a server-rendered fallback page (§1.1).

Checkpoint: before building E7, send me (in Chinese) the geometry spec, a screenshot of a rough prototype with real data, measured frame times, and the layout JSON size. Wait for approval.
