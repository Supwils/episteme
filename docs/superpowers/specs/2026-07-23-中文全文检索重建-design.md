## 1. 问题

平台有 2288 篇内容，但**中文检索基本失效**。

`lib/search-index/index.ts` 用 MiniSearch 的默认分词器，它按空白与标点切分（`[\n\r\p{Z}\p{P}]+`）。中文句子内部两者都没有，于是**整个标点分隔段落成为一个 token**，检索退化为"从词头猜"。

实测（2288 篇真实内容，自动生成 ground truth，判定标准 recall@5）：

| 分词器              | 标题中段查询 | 正文短语查询 |
| ------------------- | ------------ | ------------ |
| 默认（现状）        | **9%**       | 0–10%        |
| `Intl.Segmenter`    | 83–87%       | 34%          |
| **bigram 二元切分** | **100%**     | **100%**     |

具体表现：文章《熵与热力学第二定律》，搜「熵」命中（是前缀），搜「热力学」**搜不到**（在 token 中部）。

第二个缺陷：所有 indexer 的 `content` 字段填的是面包屑（`` `${a.category} · ${a.sectionLabel}` ``、`` `${thinker.era} · 哲学家` ``），**2288 篇文章的正文一个字都没进索引**。

第三个缺陷：索引在浏览器里现建——`getSearchIndex()` 动态 import 约 38 个内容数据模块再建索引，既慢又把内容数据拖进客户端。

第四个缺陷：`app/page.tsx` 的 JSON-LD 声明了 `SearchAction → /search?q={q}`，但 `/search` 路由不存在。

## 2. 度量与选型依据

全部为本机实测（Node 22，2288 篇，10.05M 正文字符）。

**客户端索引（bigram，`storeFields: []`）**

| 深度            | brotli    | `loadJSON` | 标题中段 | 小标题 | 正文短语 |
| --------------- | --------- | ---------- | -------- | ------ | -------- |
| 仅标题          | 56KB      | 28ms       | 100%     | 1%     | 0%       |
| **标题+小标题** | **403KB** | **363ms**  | **100%** | 100%   | ~0%      |
| +摘要 200 字    | 991KB     | 1050ms     | 100%     | 100%   | 低       |
| 全文            | 9.9MB     | **6792ms** | 100%     | 100%   | 100%     |

全文索引不可行：6.8 秒加载，构建期吃 4GB 堆。

**服务端正文暴力扫描（无倒排索引）**

```
语料 9.8MB · 冷启动（读盘 + parse）67ms · 查询 0.2–4.3ms（均值 1.3ms）
```

结论：正文精确短语检索**不需要倒排索引**，`indexOf` 扫 10MB 足够快。

## 3. 架构

两层，各自解决一类查询意图。

```
用户输入
   ├─ 第一层（客户端 Worker，即时，0 网络往返）
   │    bigram MiniSearch over 标题 + 小标题 · 403KB · 100% 召回
   │    → 意图：「我大概知道它叫什么」
   │
   └─ 第二层（服务端 /api/search，防抖后请求）
        10MB 语料暴力短语扫描 · 1.3ms · 精确短语 + 上下文摘要
        → 意图：「我记得里面有这么一句」
```

两层结果在 UI 中分组呈现：「标题匹配」/「正文中提到」。

## 4. 组件

### 4.1 `lib/search/tokenize.ts` — 分词器

纯函数，构建期与浏览器**共用同一份实现**。索引侧与查询侧分词不一致会静默返回空结果，因此必须单一来源。

```
CJK 连续段 → 二元切分    热力学第二定律 → 热力,力学,学第,第二,二定,定律
拉丁/数字   → 整词小写    WebGL → webgl
单字 CJK    → 原样保留    熵 → 熵
```

依赖：无。不引入分词词典或 WASM。

### 4.2 `scripts/gen-search-index.ts` — 生成器

并入 `gen-all`（因而被 `prebuild` 与 CI 的"生成索引零差异"门禁覆盖）。单次遍历 `content/` 产出：

| 产物                         | 体积   | 入库                                           | 消费者 |
| ---------------------------- | ------ | ---------------------------------------------- | ------ |
| `public/search-index.json`   | ~403KB | ✅ 入库（同 `public/link-previews.json` 先例） | 第一层 |
| `generated/corpus.txt`       | ~10MB  | ❌ gitignore，`prebuild` 重生                  | 第二层 |
| `generated/corpus-meta.json` | 小     | ❌ gitignore                                   | 第二层 |

语料存**纯文本 + 偏移表**，不存单个巨型 JSON 字符串——`JSON.parse` 10MB 实测导致 350MB RSS 峰值。

开发环境语料缺失时，`/api/search` 首次请求就地生成并缓存于模块作用域（约 2 秒），`pnpm dev` 不受影响。

### 4.3 第一层：`lib/search/search.worker.ts`

沿用仓库已有 Worker 先例（`subjects/knowledge-graph/engine/force-layout.worker.ts`）。

**约束**：`new Worker(new URL(...))` 内**必须使用相对路径**——`@/` 别名在 Turbopack 中不解析，会静默失败为 `[object Event]`（见 `subjects/history/components/history-graph/useHistoryGraphRenderer.ts:277` 的既有注释）。

Worker 内 `MiniSearch.loadJSON` + 查询，主线程零阻塞，保护既有 TBT 预算。无 Worker 环境降级为主线程同步加载。

副作用：删除 `lib/search-index/index.ts` 中的 38 个 `import("@/content/...")`，minisearch 移出主 bundle。

### 4.4 第二层：`app/api/search/route.ts`

模块级单例加载语料（Fluid Compute 复用实例 → 冷 67ms，热 0）。`indexOf` 扫描 → 偏移二分定位文档 → 返回标题 / URL / 学科 + 上下文摘要。

- 输入边界：CJK 查询 ≥2 字，拉丁 ≥3 字符；`limit` 上限；命中数上限。
- 缓存：`Cache-Control: public, s-maxage=86400`（内容仅随部署变化）。
- 零命中降级：退化为 bigram AND 语义（实测「自然选择的单位」精确短语 0 命中）。

### 4.5 UI

- `components/GlobalSearch.tsx`：第一层即时出结果，第二层防抖后追加，分组展示。
- `app/search/page.tsx`：独立结果页，可分享、可 SSR、带学科/类型分面。修掉 JSON-LD 的失效声明。

## 5. 门禁

不做这些 CI 必红：

1. `scripts/performance/rendering-strategy-audit.mjs`：`/api/search` 加入 `DYNAMIC_ROUTE_HANDLERS`（7 → 8）；`/search` 按实际渲染方式登记。
2. `scripts/physics/bundle-check.mjs`：为 `public/search-index.json` 新增体积预算（450KB brotli），防索引悄然膨胀。
3. **召回率回归测试**：固定标注集断言标题中段 `recall@5 ≥ 95%`。这是防止再退回 9% 的唯一真保险。
4. E2E：模态用标题中段词命中文章；`/search` 页渲染；正文短语查询命中正确文章。

## 7. 明确不做（本期）

- **不治理内容真相源分裂**：`content/*/…-data.ts` 镜像模块保留。新管道直接从 MDX 生成，不再依赖镜像，但不删旧模块（它们仍服务路由与图谱）。退役留待下期。
- 不引入外部检索服务（Typesense / Algolia / Upstash）。2288 篇文档用不上，且会引入密钥管理、索引同步与供应商锁定，违背当前无后端无 DB 的架构优点。
- 不做同义词、拼音检索、typo 容错。
