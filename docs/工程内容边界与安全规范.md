# 工程内容边界与安全规范（T-SUBJECT-ENG launchGate）

> 2026-08-03 · 本规范是「工程与技术」域内容生产的前置闸门。所有工程域文章必须遵守；check-content 层面的强制检查项随首波内容落地时补充。

## 一、领域定位

工程域讲的是**人造物如何被可靠地造出来**：能量、材料、系统、基础设施、设计与失效。它是知识解释，不是操作手册。

## 二、军民两用内容边界

工程知识天然有军民两用性。本平台的原则是**「教科书级公开知识可以讲，可操作的关键细节不给」**：

**可以写**：

- 原理与机制（反应堆如何临界、火箭如何入轨、芯片如何光刻）
- 历史与制度（曼哈顿工程的组织、半导体产业政策）
- 系统级权衡（电网稳定性、结构安全系数、失效分析）
- 教科书级公式与公开数据（卡诺效率、桥梁荷载等级）

**不可以写**：

- 武器级材料的可操作参数（浓缩方法的具体工艺参数、起爆装置设计）
- 可直接用于破坏的具体步骤（入侵关键基础设施的方法、绕过安全联锁的操作）
- 双用途生物/化学工艺的可复现细节（与医学域的生命伦理规范一致）

判别口径：**一份合格的公开大学教科书里能找到的，可以写；需要专业资质或许可才能接触的细节，不写。** 拿不准就不写，或概括到系统层面。

## 三、工程安全提示

- 涉及高压、高温、危化品、结构作业的段落，必须有「专业资质与监管」提示——参照医学域「不构成医疗建议」的做法，工程域文章涉及实操风险时写：**本篇为原理性通识解释；任何工程作业须由持照专业人员按当地法规执行**。
- 不鼓励 DIY 高危系统（家用高压电、自制压力容器等）；提到它们时只讲原理与监管逻辑。

## 四、数据时效

- 工程数据（装机容量、桥梁纪录、制程节点）随项目进展快速过时：frontmatter 用 `as_of: YYYY-MM` 标注口径日期；正文写「截至 X 年」而非「目前」。
- 纪录类表述（最高楼、最长桥）必须带年份与来源。

## 五、与其他域规范的衔接

- 图像：一律走 `docs/图像管线指南.md`。
- 事实纪律：同全平台——年份/数据/人物全部 WebSearch 核实，无法核实概括化或删除。
- 跨域连接：按 `T-CONTENT-40` 达标口径（≥4 bullet、≥3 粗体链接、≥400 汉字、无自链）。
