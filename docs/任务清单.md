7. **`T-RENDER-01` 软 404：已按路径 B 修复**（2026-08-05 定位并落地）。实验证据：移走 `app/sociology/loading.tsx` 重新构建后，`/sociology/concepts/zzz-nope` 由 `200` 变为 **`404`**，真实文章不受影响；恢复该文件后回到 `200`。对照实验同时确认根 404 机制本身完好（`/this-route-does-not-exist-at-all` 与 `/sociology/zzz-section` 均正确返回 404），**问题只出现在被 `loading.tsx` 包裹的动态 `[slug]` 路由上**。机制：`loading.tsx` 在段级创建 Suspense 边界，Next 立即流式输出外壳（`200` 头已发出），此后 `notFound()` 只能改变正文、无法改变状态码。全站现有 **160 个 `loading.tsx`**，均为 `T-UX-05`（会话 #220）为改善首访体验而加。

   | 路径                                      | 做法                                                                                 | 代价                                                                        |
   | ----------------------------------------- | ------------------------------------------------------------------------------------ | --------------------------------------------------------------------------- |
   | **A. 保持现状**                           | 接受软 404                                                                           | 搜索引擎可索引无限多 200 页面；坏链无法靠状态码监控发现                     |
   | **B. 移除文章页祖先链上的 `loading.tsx`** | 骨架屏改为列表页组件内的显式 `<Suspense>`，使 `[slug]` 段无祖先 Suspense 边界        | 文章页首访（按需 ISR 生成期）失去流式骨架；改动面约 160 个文件              |
   | **C. 中间件预校验**                       | 用已生成的 slug 集合（`wiki-link-index` 共 2939 条）在中间件拦截未知 slug 并返回 404 | 每请求增加一次查表；slug 集合进入中间件包体；新增一层需长期维护的运行时依赖 |

   **不可行的选项**：给高基数 `[slug]` 返回全部 slug 或关掉 `dynamicParams`——直接违反 15000 文件上限（见第二节禁令）。

   **已采纳 B（用户拍板）**：移除位于动态段之上或之处的 **117 个** `loading.tsx`，保留 **43 个**（其所在子树无动态段——恰好是知识图谱、Atlas、地图、模拟器这类最需要骨架屏的重页面）。三个共享骨架组件（`components/loading/`）随之成为零引用孤儿，一并删除。**代价明确记在此处：文章页与领域/板块列表页失去客户端导航的即时加载态**；`loading.tsx` 提供的即时态无法用页面内 `<Suspense>` 复现，这是该路径不可避免的损失。
