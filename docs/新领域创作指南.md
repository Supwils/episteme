# 新领域内容创作指南（通用领域引擎驱动的 11 个域）

> 适用于由通用引擎（`lib/knowledge-domain.ts` + `lib/new-domains.ts`）驱动的领域：
> `computer-science`、`political-science`、`earth-science`、`medicine`、`chemistry`、`sociology`、`psychology`（methods 板块）、`linguistics`、`law`、`arts`、`engineering`。
>
> 范文：`content/computer-science/pioneers/alan-turing.mdx`、`content/political-science/thinkers/thomas-hobbes.mdx`。动笔前先读它们、`docs/知识精神.md` 与 `docs/叙事与引用规范.md`。
>
> **新建一个领域**（而不是给已有领域写条目）是另一回事：走 `docs/学科版图与导航架构.md` 第五节的八阶段 Playbook，且需用户拍板立项。

---

## 1. 文件位置

- 板块条目：`content/<领域>/<板块>/<英文-kebab-slug>.mdx`
- 前沿条目：`content/<领域>/frontier/<slug>.md`（**.md**，遵循 `docs/前沿创作指南.md`）

各域板块以 `lib/new-domains.ts` 的 `sections` 为准（板块 key = URL 段 = 内容子目录名）。当前示例：

| 领域              | 板块                                                                                                                                   |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| computer-science  | pioneers · concepts · algorithms · theory                                                                                              |
| political-science | thinkers · isms · concepts · institutions · international-relations · methods                                                          |
| earth-science     | pioneers · concepts · processes · events · climate-risks                                                                               |
| medicine          | figures · concepts · diseases · technologies · public-health · ethics · traditions · events                                            |
| chemistry         | figures · concepts · substances · reactions · methods · milestones                                                                     |
| sociology         | thinkers · concepts · institutions · methods                                                                                           |
| linguistics       | sounds-and-signs · words-sentences-meaning · acquisition-and-mind · history-typology-society · writing-systems · methods-and-frontiers |
| law               | foundations · public-law · private-law · criminal-and-procedure · legal-traditions · global-and-digital                                |
| arts              | foundations · traditions · media · architecture · aesthetics · methods                                                                 |
| engineering       | foundations · energy · materials · machines · civil · frontiers                                                                        |

**板块 key 必须与 `sections` 完全一致**——目录名写错不会报错，只会让文章不出现在任何列表里。

## 2. 板块条目 frontmatter（通用引擎读取）

```yaml
---
title: 克劳德·香农 # 中文标题（必填）
title_en: Claude Shannon # 英文（可选但建议；含半角冒号 ": " 必须加引号）
status: published # 必填
updated: 2026-08-04 # 必填 YYYY-MM-DD；⚠️ 不加引号会被 gray-matter 解析成 Date
category: 理论奠基 # 用于列表分组与筛选 chip（同板块务必复用少数几个写法）
order: 2 # 同板块排序，小的在前（可选；同 category 内不要撞号）
tags: [信息论, 熵, 通信] # 3-6 个
related: [alan-turing] # 同板块内的其他 slug（可选，会做完整性校验）
# —— 以下"信息字段"会自动出现在文章右栏，按需填写 ——
years: 1916–2001 # 生卒（人物）
nationality: 美国 # 国籍 / 地区（人物）
field: 信息论 · 通信 # 领域 / 分支
era: 当代 # 时代（思想家/主义可用）
period: 冷战 # 时期
region: 西方 # 地区
key_figures: [香农, 图灵] # 关键人物（主义/制度/概念可用，数组）
as_of: 2026-06 # 快速过时的数据口径日期（工程域强制，见工程内容边界规范）
---
```

> 引擎把出现的 `era/period/years/nationality/region/field/key_figures` 自动渲染到右栏"条目信息"。人物板块建议填 years/nationality/field；主义/制度/概念建议填 era/key_figures/region。
> `category` 写法混用会在板块页生成重复筛选 chip（工程域上线时踩过），同板块统一。

## 3. 正文结构（建议骨架，按主题调整）

1. 开篇钩子：一个具体场景/年份/人物切入。
2. `## 破除误解`：常见但过浅的理解。
3. `## 现场 / 核心`：把核心思想或机制讲清楚，为什么重要。
4. `## 结构 / 展开`：分点、对比（鼓励用表格对比不同流派/方法/路线）。
5. `## 代价与争议`：局限、批评、对立观点（务必呈现争论双方）。
6. `## 跨域连接`：**达标口径 ≥4 条 bullet、≥3 条粗体 `[[slug]]` 领头、≥400 汉字、无自链**（`pnpm audit-cross-domain` 强制）。
7. `## 参考文献` / `## 延伸阅读`：语义分离，标题不用变体（见 `叙事与引用规范.md`）。

深度要求：**≥ 2200 汉字**（主口径）或达到 `scripts/check-content.ts` 的 `MIN_LINES` 行数下限（辅助口径，为公式/表格密集型文章保留）；两者满足其一即达标。

## 4. 写完之后必须做的注册动作

新增文章不是"写完文件就完了"。按域不同，还要：

1. **图谱节点——不用手写了**（`T-GRAPH-16`，#249）。18 个文件型域的文章只要落在 `derived-node-taxonomy.ts` 已登记的板块里，`mdx-derived-nodes.ts` 就会在模块加载时从 frontmatter 派生节点与边。**代价是覆盖率底线全部提到了 100%**（哲学 98%），所以文章放错板块或新开板块忘登记，`audit-graph-coverage` 会立刻红。
   - 想让新文章**多带几条边**，就在 frontmatter 的 `related` 里写同域文章的 slug（跨域也行，slug 全平台唯一时才解析）。什么都不写也能入图，但只会拿到一条通往领域入口的锚点边。
   - 仍要手写节点的只剩**策展锚点**（`<域>-nodes.ts` 里那些没有文章、专门用来搭骨架的节点）。手写节点的 `prerequisiteIds` **必须同时是图上邻居**（既低一级、又有边），否则是孤儿节点——这个坑踩过五次。
2. **linguistics 额外两道闸门**：`lib/linguistics-subject-plan.ts`（板块清单 + 发布波）与 `lib/subject-candidate-matrix.ts`（篇数计数）。**这是全仓库注册负担最重的域。**
3. **`pnpm gen-all`**：重生搜索索引、wiki-link 与反链，产物一并提交。
4. **验证**：`pnpm check-content` → `pnpm audit-cross-domain` → `pnpm prepush`。
   - ⚠️ **`check-content` 带 warning 时仍以 0 退出**，警告行会被 `prepush | tail` 的测试输出淹没。**要单独跑一次并读 `Warnings:` 计数**——2026-08-05 就因此漏报过三条失效的 `related` 链接。

## 4 之补：**新增一个板块**（不是新增文章）要登记三处

给已有领域加一个新板块，缺一处就有一个隐性缺陷，且只有第一处会立刻报错：

| 顺序 | 文件                                                       | 漏掉的后果                                                                              |
| ---- | ---------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| 1    | `lib/new-domains.ts` 的 `sections`                         | 板块不存在，路由 404                                                                    |
| 2    | `derived-node-taxonomy.ts` 的域 `sections` + 层级 / 类型表 | 该板块的文章全部不入图；`derived-node-taxonomy.test.ts` 会点名报出 `<域>/<板块>` 并变红 |
| 3    | `content-reachability-audit.ts` 的对应 scope               | **该板块成为覆盖率审计盲区**（静默，无报错）                                            |

第 2 处的层级表决定节点的 `knowledgeLevel`，**派生节点自带层级、不再走 `cognitive-metadata.ts` 的 `inferKnowledgeLevel`**；后者现在只对手写的策展节点生效。若确实要改它，**不要用路由子串匹配**——`writing-systems`、`operating-systems`、`distributed-systems` 的 URL 都含 `systems`，子串写法会把大批无关节点误升级；用精确的 `domain + section` 判断，并挑一个含该子串的既有板块做反向对照。

第 3 处若该板块不是"一文一路由"（注册表驱动、或路由 slug 是 `类目--slug` 复合式），**就不要放进 scope**，否则审计会把真实路由误报成"无文章的图谱 URL"。把它留在 scope 外，并在 `derived-node-taxonomy.test.ts` 的豁免表里写明理由。

路由薄壳只需两个文件（列表页 + `[slug]` 页），照抄同域已有板块即可；**不要给 `[slug]` 加 `loading.tsx`**——它会让未知 slug 退化成软 404（见 `任务清单.md` 决策记录第 7 条）。

## 5. 事实纪律（最高优先级）

- 凡具体年份/数据/人名/论断，用 WebSearch 核实；**绝不编造**人名、论文、数据、引语。
- 区分"已确证"与"有争议/推测"；在世/已故要核实。
- 引语必须可溯源，否则转述或标"传"。
- 政治、法律、医学内容尤其敏感：**呈现争论各方，不做单方面价值裁决**；医学写"不构成医疗建议"，工程写"须由持照专业人员执行"（见 `docs/工程内容边界与安全规范.md`）。
- 核实不了的说法**直接不写**，不要写成"有研究表明"。

## 6. 语言

中文正文；专有名词、人名英文原名首次出现可并列（如 香农 Claude Shannon）；代码/slug/变量英文。
