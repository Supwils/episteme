# 内容深化轮指南

> 「深化轮」= 对某个已有领域同时做两件事：**补明显空白** + **打磨既有薄文**。一个领域一个代理（或一组），编排者统一验证。

## 两项任务

**任务 A — 新增内容**：补该领域的明显空白，写 WebSearch 核实过的新文章。
**任务 B — 改善叙事**：挑该领域现有 3–5 篇较薄或平淡的文章深化打磨（补机制、数据、争议、跨域连接、来源），**不破坏 frontmatter**。

> 先诊断再写。历史经验：三域深化轮（`T-CONTENT-49`）一开始以为"文章不够深"，实测最短也有 2314 汉字——真正的缺口是 **L4–L5 板块系统性偏薄**（frontier / methods 只有 5–7 篇）。**先量，再写。**

## 如何新增（按内容组织方式）

动笔前先 `ls` 目标目录并**读 2–3 个现有文件**，照抄其 frontmatter 形状与 slug 风格。

| 领域类型                                                            | 新文章位置                              | 附带注册动作                                                                        |
| ------------------------------------------------------------------- | --------------------------------------- | ----------------------------------------------------------------------------------- |
| **类型化 MDX**（philosophy / economics / psychology / mathematics） | `content/<域>/<子类>/<slug>.mdx`        | 搜索镜像 `*-data.ts` 由 `pnpm gen-philo/gen-econ/gen-psych` **自动生成**，不要手写  |
| **知识库**（universe-physics / cosmology / human-history）          | `content/<域>/knowledge-base/<slug>.md` | 由 `pnpm gen-kb` 自动生成索引                                                       |
| **生命科学**                                                        | `content/life-science/<类>/`            | 注册表驱动（species/scientists/extinctions 在 `subjects/life-science/lib`），须同步 |
| **通用引擎域**（11 个，见 `新领域创作指南.md`）                     | `content/<域>/<板块>/<slug>.mdx`        | 无 data 文件；但注意图谱节点与 linguistics 的额外两道闸门                           |
| **研究前沿**（任意域）                                              | `content/<域>/frontier/<slug>.md`       | 自动发现，遵循 `前沿创作指南.md`                                                    |

写完统一跑 **`pnpm gen-all`**（不是只跑某一个 gen-\*），把生成产物纳入改动。

## 写作标准（遵循 `知识精神.md` 与 `叙事与引用规范.md`）

- "顶级教授讲课"式：有现场感、有结构、有争议意识、有跨域连接（用 `[[slug]]`，写前用 `pnpm wiki-slug` 查真实 slug）。
- 篇幅：**≥2200 汉字**为主口径（frontier ≥1800），行数下限为辅助通道；两者满足其一即达标。
- `## 跨域连接` 达标口径：≥4 条 bullet、≥3 条粗体 `[[slug]]` 领头、≥400 汉字、无自链。
- 结尾区分 `## 参考文献`（佐证）与 `## 延伸阅读`（选读），来源是真实出版物。

## 事实纪律（最高优先级）

- 凡具体年份/数据/人名/论断/引语，用 WebSearch 核实；**绝不编造**人名、论文、机构、数据、名言。不确定就概括，不要造看起来很具体的"事实"。
- 区分"已确证"与"有争议/推测"；在世/已故必须核实（曾出现把 2026 年才去世的学者按在世写的风险）。
- frontmatter：`status: published`、`updated: YYYY-MM-DD`；含半角冒号 `: ` 的 `title_en` 或列表值必须加引号，否则 YAML 解析失败。

## 分工硬约束（多代理并行时）

- 只动**本领域**的 `content/<域>/` 与其注册文件。不要碰 `lib/`、`app/`、`components/`、`scripts/`、其他领域——除非编排者明确指派。
- 子代理不要跑 `pnpm build` / `dev` / `typecheck`（编排者统一验证）；可自行跑 `pnpm check-content`。
- 完成后报告：新增文件（slug + 一行摘要）、深化的文件（改了什么）、更新的注册项、**无法核实而主动省略的内容**。

## 编排者收口清单

```bash
pnpm gen-all && git status --short   # 索引与内容一致
pnpm check-content                   # 0 error / 0 warning
pnpm audit-cross-domain              # 跨域连接达标
pnpm prepush                         # 九条门禁全绿
pnpm build && pnpm bundle-check -- --skip-build   # 搜索索引预算别被写爆
# 新路由逐条冒烟（注意 dev 端口 3067）
```

**并行写作后必须多做一步：板块内连接性检查。** 单篇质量高不等于板块成形——2026-08-05 的三批系统剖析里，前 16 篇彼此**零引用**，是一堆互不相识的好文章。批量产出的默认结果就是孤岛，因为写手看不到彼此。收口时用下面这段查一遍，按真实机制线索（而非随意配对）补 `related`：

```bash
python3 - <<'EOF'
import re, glob, os
files = sorted(glob.glob('content/<域>/<板块>/*.mdx'))
slugs = {os.path.basename(f)[:-4] for f in files}
inb = {s: 0 for s in slugs}
for f in files:
    rel = set(re.findall(r'^  - (\S+)$', open(f).read().split('---')[1], re.M)) & slugs
    for r in rel: inb[r] += 1
print("入链为 0：", [k for k, v in inb.items() if v == 0] or "无")
EOF
```
