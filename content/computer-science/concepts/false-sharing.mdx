# 伪共享不是数据竞争

伪共享是两个线程写的变量不同，变量却落在同一条缓存行上，于是一次写入让对方的整行失效。它不是数据竞争。数据竞争是多个线程无同步地访问同一内存，并且至少一个在写。一个看地址是否相同。一个看硬件是否把不同地址捆在同一行里搬走。

[[concurrency|并发]]把失效之后的总线行为写成来回打乒乓。它写：看起来没有数据竞争，吞吐却断崖下跌。[[memory-hierarchy-caching|内存层次与缓存]]写：缓存行通常 64 字节。MESI 一类协议以行为单位。一个核写入，另一个核的整条行失效。两个逻辑上毫不相干的变量会被硬件强行同步。性能可能暴跌一个数量级。修复在两页都是填充，让热点彼此不占同一行。本页只用这些已经写出的句子。不另造总线步骤，也不写怎样布置内存去测量或放大侧信道。

## 三张表不能并成一张

数据竞争是一种执行性质。同一内存，没有同步，至少一次写。竞态条件更抽象。结果依赖事件的相对时序。并发页写，两者可以分开出现。锁可以消掉全部数据竞争，加锁的粒度或顺序仍可以让结果错。某些无锁算法有数据竞争，逻辑仍可以正确。加了锁，不等于并发正确。

伪共享落在第三张表上。并发页把它写成隐性成本，并写正确性与性能是两张诊断表。没有数据竞争，只说明没有那种无同步的同一地址访问。它不说明吞吐还在。有数据竞争，也不说明缓存行正在乒乓。无锁算法可以又有数据竞争又逻辑正确。伪共享可以没有数据竞争而吞吐下跌。两种「有没有竞争」都不等于「结果对不对」，也不等于「快不快」。

缓存页的「强行同步」是协议以行为单位的后果。它不是程序员写下的锁，也不是数据竞争定义里的「无同步」。硬件在行的粒度上使副本失效。程序在变量的粒度上仍可能各写各的。把失效叫成数据竞争，会把不同地址说成同一内存。把数据竞争叫成伪共享，会把同一地址说成仅仅是邻居。

## GIL 的三句不能改名

[[cpython-gil|CPython 的 GIL]]是进程里的一把互斥锁。同一时刻只允许一个线程执行 Python 字节码。它不是语言标准。1990 年代它让引用计数保持简单。2023 年 PEP 703 被接受，目标是让这把锁可选。Python 3.13 给出实验性的自由线程构建。这些年份只交代那一页把锁放在哪。它们不是伪共享的定义。

那一页有三句必须分开的话。第一句：GIL 从未给你数据竞争自由。它只保证字节码评估不会在两个线程里同时发生。两个线程交替做 `x += 1`，即使每次加减在锁下是原子的，复合操作仍可能交错。这是同一对象上的交错。它是竞态可以留下的形状。它不是两个不同变量共享一行。

第二句：David Beazley 在 2010 年前后的实验里，多核上的计算线程和 I/O 线程为了抢这把锁互相折磨，总吞吐甚至差过单核。那一页把它写成调度与锁粒度在多核缓存一致性下的真实价格。锁很粗，于是所有线程都在打同一面墙。同一面墙是一把锁。伪共享没有这把唯一的锁。本页不把 2010 年的吞吐倒挂改名叫伪共享。缓存一致性在这句里是粗锁的价格环境，不是 64 字节那一行的别名。

第三句：即使构建去掉了这把锁，纯 Python 循环仍受字节码调度、对象分配和缓存行争用限制。两个线程改邻近对象，会把引用计数所在的缓存行打脏。偏向计数降低单线程税。对象一旦真被共享，同步仍然发生。这句用的是「邻近」和「打脏」。缓存页用的是「毫不相干的变量」和「整行失效」。并发页用的是「乒乓」。三套说法都在允许的来源里。本页不把「邻近对象的计数」收成数据竞争，也不把 Beazley 的同一面墙收成填充能治的那一行。

去掉锁之后，每一个仍假定独占的扩展，都是潜在的数据竞争。那是同一对象被并发摸到。它和「不同变量落在同一行」仍是两张表。自由线程不自动制造伪共享，也不自动取消伪共享。

## 流水线里的冒险不是这张表

[[cpu-pipelining|CPU 流水线]]不是多核。多核是多条流水线。流水线是一条流水线里，不同指令的不同阶段同时在走。一个核内部的重叠，不是两个线程各写一个计数器。

数据冒险是后一条指令要用前一条刚算出的数。硬件可以停一拍，也可以把结果从运算器侧面送过去。这是同一条指令流里的依赖。它不要求两个线程，也不要求两个变量共用 64 字节。结构上的另一句在缓存页：L1 分成数据缓存和指令缓存，为的是避免取指令和取数据竞争。这里的竞争是一个核里的两类访问抢结构。它不是数据竞争定义里的同一内存，也不是伪共享定义里的两个写者。

流水线页还记下，为了填满流水线而做的预测和乱序，会在缓存时序上留下不该留下的裂缝。本页不写如何测量这道裂缝，也不写如何把裂缝放大。伪共享的来源句停在失效、乒乓、数量级和填充。侧信道的步骤不在这些句子里，本页也不补。

缓存页另写，访问一个字节会把周围 64 字节载入。这是空间局部性。伪共享是这份搬运的账单。一次只想改一个计数器，邻居的字节跟着进了同一行，于是邻居的写也变成整行失效。局部性解释为什么硬件要搬一行。它不把不同变量变成同一个程序变量。

## 破除误解

**第一个误解，伪共享是一种数据竞争。**

数据竞争要求同一内存，而且没有同步，而且至少一次写。伪共享在并发页的写法里，两个线程写的是不同变量。看起来没有数据竞争。缓存页写的是毫不相干的变量恰好落在同一条 64 字节的行里。地址不同，行相同。把行叫成内存位置，是把硬件的搬运单位说成了程序的变量。两页都没有这样说。

**第二个误解，没有数据竞争就没有乒乓。**

并发页把这两句放在相邻的段里，正是为了分开。锁可以消掉数据竞争，吞吐仍可以因为同一行而断崖下跌。反过来，数据竞争也可以出现在根本不共享缓存行的算法里。无锁而逻辑正确，是那一页的另一句。正确性表、竞态表、性能表，各留各的。GIL 保证字节码不同时评估，并不勾掉第三张表。去掉 GIL 之后的缓存行打脏，也不把第一张表自动勾上。

**第三个误解，2010 年的吞吐倒挂就是伪共享。**

GIL 页把那次现象写成抢同一把粗锁。所有线程打同一面墙。伪共享没有一面供全体争抢的解释器锁。它是不同变量的行失效。两句都提到多核上的缓存一致性。一致性在前一句里是锁的价格环境。在后一句里是行协议。环境相同，不是现象相同。填充治不了那把粗锁。删掉那把锁，也留着邻近引用计数把行打脏的那句。

填充在并发页是对齐，让热点计数器各占一行。在缓存页是加上填充字节，把变量挤到不同的行。两页都把它写成性能上的办法，不写成数据竞争的修补。本页不补充填充多少字节的配方，也不把填充写成观测侧信道的布置。一个数量级是缓存页已经写出的跌幅说法。本页不另测一个新的倍数。

## 跨域连接

- **[[graph-theory|图论]]**：并发页把死锁写成资源等待图上的环。环是进展停住，四个必要条件凑齐才会全体卡住。伪共享不在这张图上。两个计数器不必互相等待。它们只是落在缓存页所说的同一条 64 字节的行里。吞吐断崖不是环。把下跌画成死锁，会把填充误写成拆环。等待图只管谁持有谁。缓存行只管硬件一次搬走多少字节。两张图的边不是同一类关系。

- **[[memory-systems|记忆系统]]**：缓存页写，硬件一次搬 64 字节，是因为空间局部性把邻近地址当成会一起被用。伪共享是这句假定的账单。不想一起用的变量被一起搬走，一次不相干的写就让整行失效。那一页自己的跨域节还写，缓存按地址精确命中，人的记忆却会把相似内容混淆。本页只取硬件这半句。混淆不是乒乓。乒乓是并发页对总线来回失效的说法。相似不是同一内存，邻近也不是数据竞争。

- **[[proof|证明]]**：没有数据竞争，只证明没有那种无同步的同一内存访问。它不证明结果与时序无关，那是竞态条件还要单独看的事。它也不证明吞吐。并发页把正确性和性能写成两张诊断表。缓存页用一个数量级写下可能的下跌。GIL 页用打脏写下自由线程之后邻近对象仍会付的行代价。三句都是「没有数据竞争」推不出来的东西。证明停在定义覆盖的那张表上。换一张表，就要换一条前提。

- **[[reliability-engineering|可靠性工程]]**：并发页里的优先级反转是锁的正确性故障。低优先级持锁，高优先级干等，1997 年的探路者会因此被看门狗重启。伪共享不把错误结果送出去。它让不同变量的写互相废掉缓存行，答案可以仍对，时间被乒乓吃掉。只检查答案，会漏掉失效。只检查变慢，会漏掉同一地址上的数据竞争，也会漏掉复合的 `x += 1` 仍可能交错。可靠性至少要留两张表。本页不把填充或重启写成操作步骤。

- **[[opportunity-cost|机会成本]]**：填充用空间把热点计数器分开，买的是不再共用一行。并发页和缓存页都把它写成性能办法。GIL 的粗锁用全体线程的等待，买对象层协议可以保持简单。2010 年前后这笔等待的价格可以是总吞吐差过单核。两笔成本都出现在多核上。买到的东西不同。锁买到的是字节码不同时执行。填充买到的是不同变量不落在同一行。偏向计数买到的是未共享对象的快路径，共享之后同步仍在。三张账单不能加成一张，也不能互相支付。
