# 资源获取即初始化不是垃圾回收

资源获取即初始化把资源的获取绑在构造函数上，把释放绑在析构函数上。对象在，资源就有效。对象销毁，资源就释放。它不是垃圾回收。垃圾回收要运行时判断哪些内存不再可达。引用计数靠对象上的计数归零。追踪从根出发找出还活着的对象。所有权在编译期规定谁离开作用域时丢弃值。异常展开是调用栈退出时沿途调用局部对象的析构。五件事都碰释放。合同并不相同。

人物页写，这套绑法把内存安全从运行时的回收停顿挪到编译期约束，并启发了后来 Rust 的所有权系统。[[garbage-collection|垃圾回收]]页写，所有权在编译期消除悬空指针和释放后使用，却不保证绝对不泄漏。[[rust-borrow-checker|借用检查器]]页写，语言曾假设析构函数一定会运行，这个假设被泄漏打破，于是把泄漏划到安全一侧。三句都留在各自的页上。本页不把它们收成「有了析构，就不再泄漏，也不再停顿」。

## 析构覆盖的是控制流，不是可达性

人物页把资源写成内存、文件和锁。漏写解锁是人为疏忽。`lock_guard` 离开作用域就解锁，是类型系统保证的控制流。异常、提前返回、作用域嵌套，被同一套析构盖住。`unique_ptr` 把这一模式用到堆内存。`shared_ptr` 在共享所有权时，用引用计数承认唯一所有者已经被放松。这仍不是在堆里找不可达对象。

异常展开是另一句。人物页写，异常沿调用栈展开，并沿途调用局部对象的析构。正常返回会释放。中途抛出也会释放。设计从 1984 年拉到 1989 年。柯尼希与斯特劳斯特鲁普的方案刊在 1990 年。这些年份只标出展开何时把析构点亮。标题不是某人某年。

零开销在同一页是准入门槛。不用的东西不必付费。直接后果是没有内置垃圾回收，因为那份成本会落在不用它的程序上。异常不抛出时几乎零代价。这不是追踪的停顿，也不是计数器每次加减。

## 引用计数和追踪仍在垃圾回收里面

引用计数到零就立即释放。回收分散在运行过程里，没有停顿峰值。它收不了环。A 指向 B，B 指向 A，两边计数都是一，外面已经没有人指着，它们仍不会被收回。多线程里，改计数要原子操作，或者用锁。垃圾回收页写，CPython 用全局解释器锁回避原子计数，并因此限制多线程性能。朴素计数每次指针读写都改计数器，污染缓存。这是计数的账单，不是析构沿栈展开的账单。

追踪从根出发。根包括全局变量、栈上局部变量和寄存器里的值。走不到的是垃圾。标记清除能收回没有外部根的环。标记阶段要停下程序。清除之后会碎。主人是根还能摸到谁，不是构造时声明的那个对象。

2004 年，Bacon、Cheng 与 Rajan 把追踪和引用计数写成同一结构的两种看法。追踪从根做加法。引用计数从删引用做减法。高性能实现往往是混合。这句对偶停在垃圾回收内部。它不把析构收成第三种计数，也不取消环和停顿的差别。

苹果在 2011 年的开发者大会上推出自动引用计数，随后把 Objective-C 的追踪式回收标成弃用，并在 macOS Sierra 里移除。那一页给出的理由是时机确定，没有不可预测的停顿。自动引用计数仍然是计数。环仍在。它不是构造与析构那条类型合同。确定的计数和确定的析构仍要分开写。

## 所有权不是这两条回收

垃圾回收页把所有权写成另一条路。每个值有唯一的所有者。所有者离开作用域，值立刻被丢弃，编译器插入 `drop`。借用允许临时访问，并带生命周期限制。这条路被写成没有回收器的运行时开销。同一页立刻改口：它不保证绝对不泄漏。`Rc` 与内部可变性套出来的环照样泄漏。`std::mem::forget` 和 `Box::leak` 是安全接口。编译期根除的是悬空指针、释放后使用和数据竞争，不是泄漏。

借用检查器页把界线写得更窄。泄漏是安全的。两个 `Rc` 互指，谁也不降到零，不必写不安全代码。死锁、逻辑竞态、空值上的 `unwrap` 恐慌，都是安全的。排除的是未定义行为。1.0 之前曾假设析构函数一定会运行。泄漏打破了这个假设，泄漏被放在安全一侧。「作用域结束就 drop」不是「析构在一切路径上必然发生」。人物页写抛出和正常返回都会调用析构。借用检查器页不把「一定会运行」留在假设里。本页不把 Rust 的 drop 改写成 C++ 的异常展开。

移动也不相同。借用检查器页写，C++ 的 `unique_ptr` 表达唯一所有者。移走之后，旧对象仍是合法可读的，值是空指针，编译器不阻止你再读它。Rust 把移走的名字标成不可用。作用域结束时只有新所有者触发 drop。人物页把 `unique_ptr` 算作资源获取即初始化的实现。两页都在谈唯一所有者。一个允许移走后的空壳继续存在。一个把旧名字从类型状态里拿掉。本页不把这两种移动合成一种所有权。

借用检查器页排除数据竞争，靠的是另一条规则。同一时刻，要么多个不可变借用，要么恰好一个可变借用。这不是析构函数。人物页把消除数据竞争和悬空指针归给所有权类型系统，不是归给 `lock_guard`。本页不把资源获取即初始化写成数据竞争的解法。

2020 年的工程记录只说明停顿。当时的 Go 运行时每 2 分钟强制回收一次，每次扫一整块巨大的缓存，于是出现延迟尖刺。换成所有权之后，周期尖刺消失。同一页把逻辑泄漏定义成指针还在、程序却不再使用。尖刺消失，不取消这个定义，也不是异常展开。

Hertz 与 Berger 2005 年的倍数和百分数只标在回收器上。大约五倍内存可以追平手动管理。大约三倍慢约 17%。大约两倍慢约 70%。人物页的「不用就不必付费」是另一句成本。本页不合成「析构因此快百分之多少」。

1959 年，垃圾回收页把麦卡锡实现 Lisp 时的决定写成：由运行时自动回收不再使用的内存。参考文献里的论文年份是 1960。本页不把两年并成一次发表。自动判断可达，从那一页起就是回收的定义。它从一开始就不是「对象离开作用域时调用析构」。

## 破除误解

**第一个误解，资源获取即初始化就是垃圾回收。**

前者把获取和释放绑在对象的构造与析构上。后者由运行时判断不可达。人物页明确把没有内置回收写成零开销的后果。垃圾回收页把所有权写成完全不同的路径。借用检查器页把回收列为传统路径之一，旁边还有动态检测，第三条才是编译期的借用规则。三条路径在来源里是并列的。并列不是同一机制的三个名字。

**第二个误解，共享计数或自动引用计数已经把析构和回收合成了一种。**

`shared_ptr` 在析构外壳里放了计数。人物页写，这是承认唯一所有者被放松。环按垃圾回收页的缺点回来。追踪能收环，是因为没有外部根就不可达。自动引用计数选的是确定时机，不是改掉环。外壳是析构。芯是计数。`Rc` 的环同样可以泄漏，而且仍在安全一侧。

**第三个误解，有析构函数就不会泄漏，也不会停顿。**

人物页把停顿从运行时挪走，说的是不把回收器装进不用它的程序。垃圾回收页说所有权几乎不会发生忘记释放，随即写明泄漏仍可能，而且被设计成安全。借用检查器页写明「析构一定会运行」这个假设已经被放弃。三句不能裁成一句。停顿的数字，例如每 2 分钟一次，或内存倍数对应的百分之十几与百分之七十，只描述回收器。它们不描述一次作用域退出。

所以五件事要分栏。资源获取即初始化是构造与析构的绑法。异常展开是栈退出时调用这些析构。引用计数是加减到零。追踪是从根找可达。所有权是编译期的唯一所有者、移动和 drop，并且明确不把泄漏当成未定义行为。人物页的启发关系可以留下。启发不是同一合同。

## 跨域连接

- **[[commons-governance|公地治理]]**：人物页把归还写成给每份资源一个负责人，负责期与作用域重合。同一页把垃圾回收写成相反路线，取消个体责任，改由中央定期清理。引用计数仍是每个对象自己的账，只是收不了环。追踪才从根做中央扫描，并会停顿。所有权把负责人放回编译期的唯一名字。借用检查器页却承认泄漏可以安全发生。难以表达的共享、环、停顿和被允许的泄漏，不是同一种失灵。

- **[[proof|证明]]**：追踪要维持可达性。垃圾回收页不许黑对象直接指向没有灰中介的白对象，写屏障负责堵住这条路径。资源获取即初始化维持另一条：离开作用域的控制流会调用析构。异常展开把抛出也算进这些控制流。借用检查器页写它可靠但不完备。接受的程序没有那几类未定义行为。并非一切没有未定义行为的程序都会被接受。泄漏不在被排除的那几类里。三条证明不能互相代替。

- **[[opportunity-cost|机会成本]]**：Hertz 与 Berger 在 2005 年给自动回收标过价。内存大约五倍于存活数据时，吞吐可以追平手动管理。收到大约三倍，慢约 17%。收到大约两倍，慢约 70%。人物页的零开销是另一句：不用的回收器不该向所有程序收费。所有权把运行时税换成编译期的拒绝。可靠而不完备，意味着一些本能运行的程序会被错杀。五倍、17%、70% 和错杀率在来源里各是各的账。本页不加总。

- **[[identity|同一性]]**：移走之后，责任还在不在原处，两页答案不同。人物页把 `unique_ptr` 当作资源获取即初始化。借用检查器页写，移走后的 `unique_ptr` 仍是可读的空指针。Rust 把旧名字标成不可再用。drop 只发生在新所有者身上。`shared_ptr` 和 `Rc` 再把唯一放松成计数。追踪不靠这个身份，只问根还能不能走到。这几种问法不能并成一次释放。

- **[[epidemiology|流行病学]]**：人物页写，微软 2019 年的报告里，过去 12 年的安全漏洞有 70% 是内存安全问题，并说成暴露面的结构。借用检查器页写，微软安全响应中心 2019 年公布的数字是，十余年间分配的 CVE 里约 70% 是内存安全问题。一个分母是过去 12 年的安全漏洞。一个分母是十余年的 CVE。本页不平均这两个 70%，也不补来源没有写出的报告标题。人物页的对策是改变默认。借用检查器页把回收和动态检测写成前两条路径，第三条才是编译期规则。百分比和对策都不合并。
