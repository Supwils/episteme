# 事务一致性不是副本一致性

事务一致性是一笔事务结束时，数据库仍停在约束允许的状态上。它不是副本一致性。副本上的读写能不能收成一份单一历史，用的是另外的词。ACID 里的 C、CAP 里的 C、线性一致、可串行化、严格串行化，必须分开。

## ACID 的 C 看约束

[[databases-transactions|数据库与事务]]把一致性写成：事务执行前后，数据库从一个有效状态转到另一个有效状态。有效由约束定义。余额不能为负。外键必须存在。这是不变量。它不问墙上的钟，不问一次调用落在哪个瞬间，也不问字节是否在每台机器上相同。

原子性是 ACID 里的另一个字母。转账的两笔更新要么都留下，要么都不留下。[[gilbert-lynch-2002-cap|Gilbert 与 Lynch 2002]]的脚注写明，原子一致性谈的是单次请求与响应，与 ACID 里的 Atomic 不是同一个词。本页把这两个「原子」并排放下。不因为都叫原子，就把约束保持说成单次读写的线性化。

隔离性是第三件事。并发事务彼此不该互相拆台。可串行化放在这张隔离表的顶端，意思是并发结果等同于这些事务按某一次序逐个跑完。数据库页同时写，对象级的[[herlihy-wing-1990|线性化]]是另一张合同，管单对象操作何时看起来像瞬时发生，不是多行事务的隔离级别。ACID 的 C 因此也不是这张隔离表。一致性、原子性、隔离性、可串行化，在同一页里已经是四行。本页不把四行并成一行。

1983 年，哈尔德与罗伊特用 ACID 命名这组保障。1981 年，格雷把事务说成要么全做、要么不做的单元。两年都只说明命名和事务单元从哪一页来。它们不把 C 定义成副本协议。

## CAP 的 C 看单对象历史

[[distributed-systems|分布式系统]]把 CAP 里的 C 写成：读写对象表现得像单一副本，通常对应原子一致性或线性一致性。Gilbert 与 Lynch 那一页把选用的规格写成线性化的读写寄存器。必须存在一种把全部操作收成单副本顺序的讲法。不相交的实时区间不得颠倒。写已经返回之后才开始的读，不得交回写之前的值。

同一页写明两件它不是的事。它不是数据库事务里的 ACID。它不是「所有副本字节相同」。会话一致、读己之写、最终可见，是更弱的合同，不是这页的 C。三句边界都留着。分布式系统页的「通常对应」和理论页的「选用的规格是线性化寄存器」并排。它们都指向单对象读写。它们都不指向余额约束。本页不把「通常」收成「ACID 的 C 就是 CAP 的 C」。

可用性在那一页也不是机房百分比。非故障节点收到的每一个请求都必须产生响应。算法必须终止。它不给响应时间上界。分区不是第三项可以关掉的功能。它是邮件可以被丢掉。2000 年布鲁尔的口头报告用过三句口号。2002 年的注记把猜想收成一句关于执行集合的话。完全异步的消息传递网上，不存在一种实现，能在包含丢信的全部公平执行上同时保住原子一致性与可用性。

本页用这句划边界，不重放证明。推论 1.1 也只留边界。无钟模型里，不能一边要求所有公平执行都回答，一边只要求「消息其实都送到」的那些执行保持原子。原因被那一页写成：算法分不清信丢了还是信还在路上。钟和已知时限是后一节的模型更换，不是定理 1 的内容。

2012 年阿巴迪把没有分区时的延迟与一致性写成 PACELC。Gilbert 与 Lynch 页写明，这不是 2002 年的定理。分布式系统页也写，CAP 不说明正常运行时的延迟、事务隔离、持久性或故障恢复。选择要落到操作、键和不变量，而不是把整库永久标成两个字母。这些都是边界上的句子。本页不把它们编成采购清单。

## 线性一致、可串行化、严格串行化

线性一致在分布式系统页的说法是：每个操作看起来在调用与返回之间某一时刻原子发生，并尊重实时先后。它讨论单个对象的并发历史。赫利希与温在 1990 年把同一条件写成：历史要能补全成顺序规格里的一条，并且实时偏序嵌进去。A 的返回若已发生在 B 的调用之前，顺序里 A 必须在 B 前面。重叠被允许。虚构的是那个生效瞬间。规格是给定的。本页不补线性化点该插在源码的哪一行。

可串行化问的是另一类对象。若干事务各自含有多步读写。交错的结果是否等同于这些事务按某一次序逐个跑完。分布式系统页写，这个次序不必尊重墙钟。赫利希与温页写，帕帕季米特里欧 1979 年讨论的是事务之间的冲突图与等价串行序。单次调用不是多步事务。两页的分开方式不同，结论相同：可串行化不是线性一致。本页保持两套说法，不合成一句新的定义。

严格串行化在分布式系统页是：可串行化再加入实时约束。在赫利希与温页，它是把一次事务看成一个粗粒度操作时，线性化的近亲。粒度、组合方式、失败与中止的词汇仍不一样。近亲不是同一对象。本页不把严格串行化写成线性一致的数据库译名，也不把它写成 ACID 的 C。

顺序一致性被赫利希与温页用来挡住另一个吞并。它要求全体操作排成一个全局序列，并尊重每个进程自己的程序序。它不要求尊重跨进程的实时先后。写已经返回，随后才发出的读，仍可能被排到那次写前面。线性化多要的就是不相交区间不得颠倒。顺序一致性不是局部性质。线性化是。[[memory-consistency-models|内存一致性模型]]在那一页被指到硬件与编译器对地址的可见顺序。本页不把缓存协议写进来。顺序一致性不是标题里的五个词。它出现，只为了不让「强一致」把实时先后吃掉。

快照隔离也只作为可串行化的邻居出现一次。数据库页写，快照挡住脏读，仍会放行写偏斜。两名医生各自看见有人在岗，各自请假，约束「至少一名在岗」在合起来时失败。1995 年 Berenson 等人指出，用三种异常来定义隔离级别并不完备。这是隔离表的缺口。赫利希与温页写明，不把隔离级别表抄过来顶替线性化的定义。本页照做。写偏斜不是 CAP 的反例，也不是线性化点。

## 破除误解

**第一个误解，事务一致性就是副本一致性。**

事务一致性看约束在事务前后是否仍成立。副本一致性若被读成 CAP 的 C，看的是单对象读写能否收成尊重实时的单一副本历史。若被读成所有副本字节相同，Gilbert 与 Lynch 页已经拒绝。分布式系统页的「像单一副本」和理论页的「不是字节相同」并排，都不等于余额非负。三个读法不能互相翻译。

**第二个误解，可串行化就是线性一致。**

可串行化的串行序不必尊重墙钟。线性一致必须把已经结束的操作排在后开始的操作前面，而且对象是单次调用。严格串行化补上事务级的实时先后，两页仍把它留在近亲或附加约束的位置，不把它说成同一个词。分布式系统页写，把 ACID、强一致或可串行化当成同义词，会错误推断系统保证。本页遵守这句，不另造第四个同义词。

**第三个误解，CAP 是一致与可用的永久开关。**

2002 年的对象是异步网上的原子读写寄存器，外加「接到请求就要回答」和「邮件可以丢掉」。这四条叠在一起，没有实现能在所有公平执行上同时交出原子历史和响应。分区不是一项可购买的功能。定理也不是事务隔离、持久性或健康路径上的延迟。数据库页写，这并不把整座库永久标成某两个字母。本页不重讲反证，只用这句挡住开关。

五个词可以并排放。ACID 的 C 是约束。CAP 的 C 是单对象的原子读写，在这两页里对应线性化的寄存器，不是 ACID，也不是字节相同。线性一致是单对象历史加上实时先后。可串行化是多步事务的某种串行序，不必尊重墙钟。严格串行化加上事务的实时约束，仍不是把事务改名为一次线性化调用。共识算法可以去实现一份顺序日志。实现不是这五个定义里的任何一个。

## 跨域连接

- **[[philosophy-of-time|时间哲学]]**：线性一致要的时间是调用与返回的不相交。返回已经发生，后一个调用才开始，顺序里就不许颠倒。可串行化的那条串行序不必尊重墙钟。ACID 的一致性不问这根轴，它问约束。三份来源把时间放在不同的合同里。把它们收成一种「强」，墙上的钟就会冒充余额约束，或者余额约束会冒充实时先后。本页不补授时硬件，也不把等待写成新的一致性级别。

- **[[epistemology|认识论]]**：分区一侧可以已经写下新值，另一侧的证据仍和「写从未发生」分不开。Gilbert 与 Lynch 页把「真」与「知」拆开：一侧也许已经写完，另一侧没有可核验的记号。可用性不许用沉默代替回答。这是单对象历史上的认识困境。它不决定外键在不在，也不决定两笔转账是否可串行化。局部已经返回，并不等于另一侧已经知道这次写。知识的边界不能代替约束的边界。

- **[[institutional-economics|制度经济学]]**：余额不能为负、外键必须存在，是写进库里的制度。事务一致性问的是一笔事务有没有把制度打破。副本上的单一历史问的是读者看见的顺序能不能收成一份规格。制度可以在每台机器上都成立，历史仍可能违反实时。历史可以线性化，应用约束仍可能被一笔业务写破。两套检查的对象不同。把制度检查叫成副本协议，等于让账本规则去回答邮件丢了没有。

- **[[federalism|联邦制]]**：分区时，一侧继续回答还是停下来等，是 2002 年那句不可能所划的选择。数据库页把选择粒度写成操作和键，而不是整库的永久标签。联邦制页讨论的是权力放在哪一层。这里只取这个分层：唯一性一类的不变量和可以读旧的浏览，不是同一个授权。隔离级别是同一座库里的并发合同。它不是两地失联时的授权。把 CAP 的字母贴到隔离表上，会把两层政府写成同一份名单。

- **[[logic|逻辑]]**：五个谓词的变元不同。约束的变元是数据库状态。线性一致的变元是单对象的调用与返回。可串行化的变元是多步事务的交错。严格串行化在这组交错上再加实时。CAP 的原子性变元是公平执行里的读写，不是 ACID 的 Atomic。逻辑上，变元一换，句子就不能互相替换。同形的汉字不是同一条公式。本页拒绝用一个「一致性」量词盖住五套变元。
