# 项目与构型控制：基线、变更和可追到零件上的决定

## 破除误解

第一个误解，是把项目管理写成甘特图软件。图可以画得很漂亮，仍然没有回答：哪一份图纸是当前真值、谁有权改接口、改完之后哪些已经造好的件必须报废或让步。项目控制若不能把决定钉在构型上，进度只是一份愿望清单。

第二个误解，是把变更当成失败。复杂系统几乎一定会被改。构型管理要管的是**改得可追溯**：每一条变更指向哪条需求、影响哪些接口、用什么验证关闭。禁止变更的组织，最后会在现场用口头协议改，账本上却仍写着旧基线。

第三个误解，是把挣值当成会计技巧。挣值要同时看计划价值、挣得价值和实际成本。只报“花了多少”，看不见工作有没有按基线完成；只报“做了多少”，看不见钱与进度是否同步偏离。它是一组诊断指标，不是项目健康的证明书。

本篇为原理性通识解释；任何工程作业须由持照专业人员按当地法规执行。不写如何绕过变更委员会或伪造验收记录。

## 构型：把“现在到底是哪一版”写成可执行的状态

[[systems-engineering|系统工程]] 把需求分解、验证与确认写成技术过程。构型管理是把这些过程的产物锁进可识别的状态。美国国防部长期使用的构型管理实践，后来被行业标准吸收；现行公开文本的代表是 SAE/EIA-649 系列《构型管理》。它把工作拆成：识别（每项构型项有标识）、控制（基线变更走手续）、状态纪实（谁能查出当前有效文件）、审核（产品与文件是否一致）。

基线是被冻结的约定，不是文件夹里的最新草稿。功能基线锁住要满足的能力；分配基线锁住子系统之间的接口；产品基线锁住将要制造和验收的实物定义。接口控制文件若在详细设计之前不进入基线，集成台上就会出现“两边都按自己的最新邮件施工”。[[reliability-engineering|可靠性]] 指标一旦写进基线，就不再是宣传句子，而必须指向可关闭的验证方法。

变更控制委员会看起来像官僚，功能却很窄：强迫影响分析发生在金属被切之前。阿波罗登月舱减重时期，项目控制要求变更用来纠正缺陷，而不是改进已经够用的硬件——那条纪律在系统工程史里被反复引用，正因为它把“更好”从自动批准的理由里拿掉。更好永远存在；基线问的是：这一次更好是否值得打乱已经验证过的接口。

状态纪实决定事故之后能不能复盘。若现场安装的是第 17 版电缆，而质量记录仍引用第 14 版图纸，调查只能停在互相指责。审核则检查文件与实物的一致性：不是再设计一次，而是确认仓库、车间和试验室拿的是同一套真值。

## 挣值与变更：两种不同的偏离

美国国防部的挣值管理，把完成的工作用预算价格计量，得到挣得价值，再与计划价值和实际成本比较。进度绩效指数小于一，表示同样预算下完成得慢；成本绩效指数小于一，表示完成同样工作更贵。指标不会告诉你原因。原因可能是材料涨价、返工、范围蔓延，或测量本身把“几乎完成”算成完成。

范围蔓延要靠构型控制看见。每一项新增功能若只进入演示文稿、不进入基线，挣值会显示“额外工作正在发生”，却没有对应的预算与验证。[[megaprojects|超级工程]] 讨论的成本超支与乐观偏差，有一层就是：早期估算锁定的是尚未被变更过的范围，而真正建造的是被改过多次、却从未重估的范围。

丹佛国际机场的自动行李系统是项目控制失效的公开课。机场原计划一九九三年开放，实际到一九九五年二月二十八日才启用；自动分拣在规模、软件与土建接口上反复滞后，后来大部分被更传统的流程替换。争论至今仍在“技术是否过早”和“合同与变更是否失控”之间摇摆。对构型管理而言，可核对的教训是：自动化被写成单一巨大构型项，接口变更没有在土建完成前关闭，现场只能用延误吸收未冻结的决定。

波士顿中央干道/隧道工程（“大挖掘”）则把变更的政治写进了造价史。联邦公路管理局与马萨诸塞州的公开账目显示：工程造价从一九八〇年代的数十亿美元量级，上升到完工时约一百四十八亿美元的建设成本（不含利息的常用口径）。数字本身会随是否计入债务利息而变动；不随口径变动的，是变更单、未预见地质与范围调整如何把基线变成考古层。把超支只写成“美国人不会修隧道”，会漏掉账本上可逐项核对的变更。

ISO 10007 把构型管理写成质量管理的一组指南：标识、控制、纪实、审核。它不规定用哪家软件，只规定组织必须能指出当前有效的产品定义。软件仓库的提交哈希、固件版本和供应商图纸编号，若不能映射到同一构型项，召回时只能按“大概这批”来赌。数字交付没有取消构型，它只是把构型项从铁件扩到了比特。

软件物料清单（SBOM）把这一条推到供应链。一份可执行文件由哪些库、哪些许可证、哪些已知缺陷组成，本身就是构型项。若发布流水线不能指出“这一次出货对应哪一份 SBOM”，漏洞公告到来时只能全量猜测。配置管理数据库（CMDB）在运行侧做同一件事：哪一台机器装了哪一版，补丁是否关闭。仓库里的“main 分支最新”不是现场真值；现场真值是已经离开基线、进入序列号的那一版。

接口控制在软件里常常被 Pull Request 的速度掩盖。两个团队各自合并了“兼容”的改动，集成测试却在另一份尚未入基线的模拟器上变绿。绿的是模拟器，不是将要出货的组合。构型审核要问的不是测试是否通过，而是测试所针对的对象是否仍是当前有效定义。对象漂了，通过记录是另一份产品的自传。

阿波罗时代把变更分成必须纠正的缺陷与可推迟的改进。今天的持续发布把改进写成默认。两者可以共存，前提是：紧急缺陷补丁仍能指向受影响的序列号，并且补丁自己也进入基线。没有序列号映射的“全员升级”，不是构型控制，是广播。

项目控制还有一层常被写成“沟通问题”的东西：谁有权宣布基线已经切换。若产品经理在演示里用了尚未入基线的界面，销售按演示签合同，制造仍按旧产品基线备料，三份真值会在现场相遇。变更委员会若只审图纸、不审对外承诺，构型账本会永远落后于已经卖出去的故事。手续要管的不只是金属，也包括被当作规格引用的演示。

哈勃主镜的教训在项目层同样具体。辅助光学检验已经显示误差，却因为那套检验“不是被批准的主路径”而被折扣。构型控制若只保护主路径的权威，就会把独立核对事先定义成噪声。变更委员会的价值，有时不是批准新想法，而是强迫已经不方便的反证留下记录。

## 争议与边界

构型控制会被批评为创新的刹车。确实如此：走委员会的项目，改进速度往往慢于车库原型。航天、航空、核电和医疗器械接受这笔税，因为现场失败的代价不可用迭代覆盖。消费电子可以每周改固件；载人飞行器不行。标准不是普世美德，是风险预算的函数。

挣值会被批评为激励“把百分比做上去”。若完成定义含糊，承包商会先做容易被计量的工作。对策不是取消计量，而是把完成准则写进基线：什么叫关闭一条需求，什么叫可验收的试验。[[industrial-engineering-and-quality|质量工程]] 对过程能力的要求，在项目层对应的是：百分比必须对应可抽检的状态，而不是信心。

不能从构型管理推出“文件越多越安全”。挑战者号事故里，记录与测试数据并不缺，缺的是把低温密封的证据送到发射决策桌上的组织距离。手续决定信息能不能流动；文化决定它实际上流不流动。本篇不把委员会写成可靠保证。

## 为什么今天仍然重要

软件、模型和供应链把构型从金属零件扩到代码提交、训练数据和供应商图纸。数字孪生若与现场串号对不上，孪生就是另一套未受控的构型。平台公司把每周发布当成美德时，仍必须回答：哪一版固件装在哪一台已经出货的设备上，召回时如何定位。

对读者而言，这一层把“计划”从时间表改写成责任分配。谁有权改接口、谁必须重新验证、谁在审核单上签名，决定了失败之后能否找到那一个被改过却未关闭的决定。工程知识在这里变成可审计的历史，而不只是当时在场者的记忆。数字孪生、供应商门户和持续发布，只是把同一问题问得更频繁：此刻有效的定义是哪一版，证据链是否还连着那一版。

召回是构型控制的期末考试。若序列号不能映射到固件、供应商批次和已关闭的变更，公告只能写成“某年某月之后出货的产品”。范围越宽，成本越高，也越说明基线从未被当成真值。航空器适航指令之所以能点到具体件号，不是因为航空更有道德，而是因为构型纪实被写成了继续飞行的条件。消费电子可以选择不付这笔税；它付的是另一笔：无法定位时的全量猜测。

挣值在此也露出边界。百分比完成若不以构型项关闭为准，项目可以“看起来接近完工”，同时带着一堆未入基线的接口。把这两套账并在一起看，才知道延误来自做慢了，还是来自一直在做尚未被承认的另一份产品。

供应商图纸是构型项，不是附件。若供应商按自己的最新版发货，而总包仍引用两年的询价图，装配台上的冲突不会显示为“沟通不足”，而会显示为两个产品基线。接口控制文件必须把供应商纳入识别：哪一份供应商文件、哪一个修订、对应哪一条分配基线。否则变更委员会审的是内部图纸，现场装的是另一家公司的真值。

数字孪生若不能声明自己镜像的是哪一条产品基线，孪生就是第三份真值。仿真变绿、现场开裂，往往不是模型数学错了，而是模型所针对的对象已经不是出货对象。构型审核要把孪生放进同一套标识，而不是把“虚拟”当成可以不编号的空间。

未关闭的让步（concession）是构型账本上最容易被忘记的一类对象。零件超差却被批准装机，若让步没有标识、没有有效期、没有指向哪一次审核，下一轮维修会把超差当成设计意图。让步是变更的亲戚，不是沉默。它必须能在十年后被找到。

软件许可证与零件合格证一样属于产品定义。若开源库的许可证在发布后被替换，而 SBOM 仍写着旧许可，出货物与文件再次分叉。构型项包括法律状态，不只包括比特。召回和合规审查会先问文件，再问仓库。

## 跨域连接

- **[[industrial-organization|产业组织]]**：变更控制重新分配了谁承担范围风险。总包、分包与业主之间的合同，把构型项写成可计价的权利。市场结构决定变更是被合作消化，还是被诉讼放大。
- **[[io-psychology|工业与组织心理学]]**：委员会里的从众、时间压力和权威梯度，会让“反对这一次变更”变得昂贵。设计再完整的手续，仍要经过愿意在记录上写下保留意见的人。
- **[[probability|概率]]**：挣值指数是对偏离的点估计。没有把测量误差与范围不确定性分开，指数会被当成确定性预言。把 CPI 外推到完工，必须声明模型，否则只是一条斜率。同一条斜率在范围仍被改写时，描述的不是完工，而是尚未关闭的变更还在进入分母。
- **[[popper|波普尔]]**：基线的价值在于可被审核证伪——实物与文件不一致时，基线失败。不能被核对的“最新共识”，无法在事后被证明为假，也就无法被工程当作知识。
- **[[science-and-technology-studies|科学技术与社会]]**：标准、表格和委员会本身是社会装置。它们让异质的工种能引用同一套对象，也会把争议翻译成程序语言。把构型管理只写成中立技术，会看不见谁的时间表被写成了默认。一份“尚未关闭的变更”在工程师看来是风险，在财务看来是索赔权，在监管看来是未完成的符合性。同一对象，三套制度语言。构型账本的工作，就是不让这三套语言各写各的最新版。
